## 1. What was built

### 1a. Browser WASM miner prototype (local-only)

Lives in the Command Center artifact (`atlas-command-center`), inside the existing Mining tab (no new tab):

- **Miner worker** (`client/src/miner/miner-worker.ts`, 940 lines): RandomX in a Web Worker, local-only test jobs only. Reference-vector gate at load (refuses to mine on mismatch), per-solved-share single-thread re-hash self-check with drop reporting, OPFS dataset cache (fast mode opt-in, seed-keyed), 4 GiB budget enforcement, threads capped at 4, 50% duty-cycle throttle, pause-on-hidden, JIT best-effort (falls back to interpreter if CSP blocks `wasm-unsafe-eval`).
- **WASM engine:** RandomX-bonanza (aa022) pthread build — full (fast) mode in a browser — with WebRandomX single-thread as fallback when SharedArrayBuffer is unavailable. Bundled loading, not CDN. Prebuilt binaries from the official VoltMiner host (Emscripten unavailable in the sandbox, so the reproducible build recipe was not executed here); all 4 hashes match the published SHA256SUMS exactly (mt wasm `c42908af…`, st wasm `0b73579e…`). The `__thread` per-thread rounding-mode fix is confirmed in the published overlay by hash (`wasm_softround.h`, `softfloat.cpp`). Reference vector **passes** on the shipped single-thread bytes (byte-identical `086a612e…5f3`, one hash only — the only hashing done on the host).
- **Local-test relay** (`client/src/miner/miner-relay-worker.ts`): independent single-thread re-hash + exact 256-bit difficulty check (BigInt), `accepted-locally` / `rejected-locally` verdicts, `local-test` markers on every message. No socket, no pool, no forwarding. (Deviation: the relay transport is an in-page worker, not WebSocket, because the runtime exposes no WebSocket endpoint.)
- **Probe hook** (`client/src/miner/probe.ts`): `window.__atlasMinerTest` (startLocalTest / stop / status) installed **only** under `?atlas-miner-test=1` via dynamic import. Requires emergency stop ON, 600 s cap, one session per tab, accept-everything-target bisect (1/2/4 threads) as pre-test gate, difficulty-10,000 timed run, pause-on-hidden logging, full audit log. Options are structurally validated (numbers + mode enum only) so no hostname/URL/wallet can enter. No user-facing start control; no auto-run on load.
- **UI** (`client/src/miner/MinerPrototype.tsx`): "Miner Prototype — Master Mission 4" section inside the existing Mining tab: 5 gates with statuses (Gates 2/4 = NOT TESTED with reasons), measured-hashrate panel ("No measurement yet"), published-figures line (other projects' numbers explicitly labelled as theirs), desktop XMRig design summary ("Design — not built"), honest framing verbatim, WASM provenance with both SHA-256 pins + live `crossOriginIsolated`, OPFS dataset delete control, read-only test-session readout. No start control.
- **Build** (`client/build.mjs` extended): builds both workers as classic scripts into `client/dist/assets/` + copies the 4 vendor files, after the unchanged `buildClient()` call. **Deploy fix (deviation D7):** the first platform build FAILED on the one-JS-bundle rule (5 JS files in dist); fixed by embedding workers + glue as string constants in `embedded.generated.ts` (generated by build.mjs before buildClient), spawning workers from Blob URLs with a bootstrap message carrying vendor base + glue source, with only the `.wasm` binaries served as static assets. Client typecheck PASS after the fix; platform build then SUCCEEDED — `.space-build` contains the inlined bundle (probe hook + prototype section present) and both `assets/vendor/randomx/*.wasm` files, and `client/dist` holds exactly one `.js` bundle.
